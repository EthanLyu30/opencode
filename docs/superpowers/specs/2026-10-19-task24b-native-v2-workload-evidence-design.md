## 二 不变边界与方案选择

旧 C 盘 `C:\Users\Administrator\AppData\Local\Docker`、`C:\Users\Administrator\AppData\Roaming\Docker`、`C:\Users\Administrator\AppData\Roaming\Docker Desktop` 三棵树不迁移、复制、删除、恢复、覆盖、改 ACL 或改成链接；不读取旧账号、许可或 CLI credential。真实 `C:\Users\Administrator\.wslconfig` 仅核对原有文件，不修改，不新增 C 盘应用配置/缓存例外。

不重装、升级、迁移或注销 WSL/Docker，不配置既有服务，不改全局环境/PATH，不操作 Ubuntu 或全局 shutdown。原 D 盘不复制、转换、修复、压缩、合并、回滚或更换为空盘。取证不启动 daemon/发行版，不挂载 VHD，不执行盘内程序；未来获批运行仍不创建、恢复或操作容器、Swarm、Kubernetes 工作负载。

保留 v1 与现有 fixture-v2 行为、历史格式和来源隔离；不改旧视觉流程、workflow 租约/重试/预算算法、生产 `docker-config.ts`、评测题目/分组/次数、旧 dist 或现有部署。Key、`.env.local`、模型发现和付费接口不在范围内。直接沿用 dev，不另建工作树。

## 三 可信取证由谁完成

新增专用的离线读取器、固定版本存储布局目录和原生证据 broker；不接收任意路径、shell 命令、插件、数据库查询、用户自报 JSON 或 verify 回调作为真实取证来源。

先在无 Docker、无旧盘条件下完成解析器选型与能力验证：固定工具/库版本、来源、hash、依赖、文件 I/O 接口、支持的 VHDX/ext4/索引特性、拒绝分支和恶意输入回归。优先复用可审计的成熟解析能力，不为追求尽快放行临时拼接通用磁盘工具。没有满足下述要求的实现就返回 `offline_reader_unavailable`，不承诺现成工具一定可用，不静默下载、安装驱动或增加 WSL 发行版。

读取器只获得 broker 打开的两个现有普通文件的受限只读访问：

- `D:\Applications\DockerWSL\main\ext4.vhdx`。
- `D:\Applications\DockerWSL\disk\docker_data.vhdx`。

broker 绑定准确祖先、规范路径、volume/file ID 和原注册，使用 v2 bigint 身份，不将原盘作为可写 publication 根。子进程不得根据盘内字符串自行打开主机文件。差分父盘、外部日志、路径跳转或其他依赖一律拒绝，不跟随到 C 盘或第三块盘。

延续 SW 的威胁边界：可信本地控制器与已审查读取器不是抵抗同 SID 恶意进程/管理员的 OS 安全沙箱。正常竞争 writer、路径交换和外来实例仍须检测并拒绝，不能借此排除普通并发风险。读取器如需更强沙箱、驱动或额外权限，先另提准确需求，不暗中扩大本规格。

只读取固定布局目录要求的 VHDX/分区/文件系统结构、启动映射和工作负载索引元数据；不遍历镜像层、业务卷、用户家目录、容器文件系统或业务文件内容，不执行启动脚本。底层读取应通过有界 broker，越界、循环、越权逻辑路径和超限请求直接拒绝。

隐私边界必须如实展示：文件系统目录项、容器索引名及数据库元数据页可能包含敏感标识，物理页还可能夹带其他字段。字段级最小化不等于物理层绝不触及夹杂字节。真实授权须明确覆盖所需结构页读取；禁止主动定位、解码、回显或保存 credential、Env、命令参数、secret、原始页或业务值。无法做到选择性解码/脱敏的格式返回阻断，不转为全盘导出或日志 dump。不得打开项目 `.env.local` 或已知凭据逻辑文件。

## 四 只读性与数据一致性

### 不挂载，不回放，不修复

不把 Mount-VHD、WSL mount、Linux mount ro、磁盘管理工具或文件系统检查器作为本路线的默认入口。ext4 即使只读挂载也可能回放 journal；不回放也不能自动推导视图完整一致。[Linux ext4 挂载说明](https://docs.kernel.org/admin-guide/ext4.html)

读取器先校验冗余头、校验和、边界和支持的版本/特性。VHDX 存在需要恢复的非空有效日志或无法确定日志状态时，仅作有界头/日志诊断后返回 `offline_recovery_required`，不解析旧视图作为安全证据；Microsoft 的 VHDX 规则要求处理恢复日志，不能绕开后把过期数据当完整状态。[VHDX Log Replay](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-vhdx/0d588e33-23a6-4c71-b27f-87d97ac3e914)

ext4 需要恢复、未知 incompatible 特性、校验失败、外部 journal、未知分区/加密/索引格式或解析遗漏时同样阻断。不向原盘、RAM overlay 或副本回放来生成本版本的通过结果；引入恢复视图需要单独规格。禁止 fsck、repair、compact、转换、合并或自动“修好再查”。

### 稳定采集与资源预算

采集前重新确认原注册/构建、两个原盘身份和未运行状态，无 Desktop/backend/VM 或冲突控制管道；既有 SYSTEM 服务既不接管也不停止。两盘及父链完整取得保护后才开始内容读取，不能把不同时间、未保护的两盘拼成证据。

文件读取只用 OPEN_EXISTING、只读权限、不共享写入或删除，并持有父链与原文件句柄；已存在冲突 writer/mapping、无法证明离线或保护不成立即停止，不强制卸载或结束外部进程。保护会短暂阻止其他程序写入原 VHD，因此真实读盘授权必须同时说明这项影响。Windows 文件共享规则可阻止不兼容打开，但不是 VM 状态或原子移交证明。[CreateFileW 共享规则](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)

拟定每次采集预算：总执行不超过120秒、解析工作集256 MiB、两盘合计物理读取512 MiB、逻辑元数据单文件1 MiB/合计16 MiB、最多100000个结构节点、脱敏报告256 KiB。计数包括重读；达到边界返回 `offline_budget_exceeded`，不把已扫描子集标 complete，不自动放大。实现若不能执行这些限制，不接触原盘。全盘 hash、全盘复制和持久化读缓存均不在预算/授权内。

主机工具、缓存和诊断只落另批的准确 D 盘 owner 根。读取器不声称控制 OS 文件缓存、pagefile 或访问时间策略；不为减少这些 OS 行为去改全局系统设置。关闭只读句柄是释放本次自有资源，不授权清理、恢复或改写原盘。

## 五 什么证据才能判为空

### 固定布局目录是前提

完整布局目录必须从准确安装、内置引擎版本、实际启动参数和数据映射链建立，并覆盖数据盘与 runtime 盘共同决定的根位置。Docker CLI 版本不能代替 daemon/containerd 版本；本机 Desktop 4.79 的内部布局不能用当前网页默认值猜测。

Docker 的一般资料表明 dockerd 与 containerd 存储可能分离，`data-root` 不自动改变 containerd 根；因此检查一个惯用目录不构成完整覆盖。[Docker daemon 数据目录](https://docs.docker.com/engine/daemon/)

目录必须固定所有可能激活的 daemon/containerd 实例及 namespace、容器注册表、Swarm 成员/任务/持久控制状态、Kubernetes 各 provisioner/静态工作负载/控制状态，以及 Desktop 扩展、模块或其他启动后可生成任务的来源。任何额外来源未排除，或实际路径/版本与目录不符，返回 `workload_layout_unproved`。本规格不预先登记猜测的 Linux 绝对路径；没有已审查目录即没有真实通过路径。

### 首版只接纳空状态

| 范围       | 必须证明                                                                | 保守拒绝                                                                                 |
| ---------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| containers | 全部可激活存储和 namespace 没有容器、task、sandbox 或其他可恢复执行对象 | 任一旧对象存在，即使当前停止或声称 restart=no 也不接纳                                   |
| swarm      | 无可恢复成员/控制状态，也无可调度服务或任务                             | 发现控制状态或无法排除重新加入后接受远端任务即阻断，不仅数本地 task                      |
| kubernetes | 无可恢复集群/工作负载状态；准确运行设置和启动链不会启用或自动 provision | 不解析 secret/etcd 内容来勉强接纳；存在未知状态、旧 provisioner 或无法排除默认创建即阻断 |

初始化数据库/目录的存在既不等于有负载，也不等于为空。只有固定格式完整解码的索引结论才可判零；本版不支持的非空数据库可以保守拒绝，不能以解析失败或未找到熟悉键当作空。残留索引、未知 namespace、损坏页和目录读取中断均拒绝。仅有镜像、卷或缓存不直接等于工作负载；但其关联元数据无法排除激活来源时仍阻断，不删除它们。

结果类型区分 `empty_at_capture`、`nonempty`、`unsupported`、`inconsistent`、`budget_exceeded`、`cancelled`；后五种均没有使用权。`empty_at_capture` 只说明该次受保护读取的完整空结论，不是启动许可。容器名、镜像、命令、Env 和任务正文不写报告；输出范围是否完整、零/非零/未知、原因、版本与摘要即可。

## 六 取证与启动之间不能漏掉的交接

现有 fixture 将只读锁保持到 use 返回，它不能原样套到真实 VHD：禁止写共享的 VHD 句柄会阻止 Docker 自己写盘；先关锁再启动又会产生未保护间隙。

因此定义两个不同对象：

1. `OfflineWorkloadSnapshot`：当前受保护读取的事实，含工具/布局/安装/源码/文档、原注册/双盘精确身份、读取集合与内容摘要、覆盖范围、状态和采集 session。报告只有它的脱敏历史投影。
2. `NativeWorkloadPermit`：仅 broker 可签发的进程内、单操作能力，除 snapshot 外还绑定已证明的原生交接规则、当前 plan/request/nonce/controller 和剩余有效期；不能从 JSON、签名文件、hash 或历史记录恢复。

**原生交接是独立的可行性门槛。** 启用 START 前必须证明：离线保护如何移交给准确的本次 backend/WSL writer；受控交接期间不存在未授权写入/旧状态变化；出现取消、超时、身份变化或竞争 writer 时不会继续启动。只在交接已发生且本次 writer 确认接管后，才可释放相应离线保护。控制器的应用锁、两次 stat/mtime/hash、文件系统通知或“窗口很短”都不能替代这条证明。

本规格不声称当前安装提供了可用的原子句柄移交 API，也不允许关闭读锁后靠事后检查补救。原生实现如找不到与固定 Desktop/WSL 兼容的可靠机制，结果明确为 `workload_handoff_unproved`；保留 native prepare/start 阻断，不把这个问题延期到首次真实启动测试。无 Docker 竞态回归必须先验证机制；夹具通过仍不能证明目标厂商实现已支持它。

prepare 也必须先满足原有全部原生兼容门槛及当次完整负载证明；取得准备权不表示真实交接已经发生。准备完成立即释放自有保护并结束，不把 workload permit 保存到 manifest。以后 start 必须独立重新采集和确认，不沿用准备时旧结论。独立取证会话结束也销毁全部 permit。

如原盘非空，或交接不可行，当前设计交付的是具体阻断与脱敏诊断；不会改 restart policy、停编排器、换盘或要求用户用“接受风险”消除 missing。任何扩大旧负载运行范围的选择都需要新规格和单独授权。

## 七 原生 v2 接入结构

### 来源与版本隔离

保留原 v1 的2+2文档集合与算法、fixture-v2 的3+3集合及已验证语义。新增固定的内部权限域 `native-v2-r1`，不将既有对象通过字符串改标变成 native。native 的 spec/plan/manifest/request 采用显式、严格的 native-v2 变体；不能以删去域字段回落 fixture 或 v1。

native 文档集合为既有3份规格加本文、既有3份计划加未来同题配套计划 `docs/superpowers/plans/2026-10-19-task24b-native-v2-workload-evidence.md`，形成准确4+4集合。此处是拟定 registry，不在本轮修改代码；配套计划不存在或未经批准时 native 绑定失败，不能填零 hash、只检查数量或借旧摘要凑齐。源码继续绑定实际干净提交树；旧未跟踪报告须另行按明确文档处理范围解决，不自动接管。

native 变体在原 `manifest.json` 中绑定域、reader/layout/lifecycle/settings/交接规则及文档集合摘要，不增加独立许可或可恢复 seal 文件。运行期 snapshot/permit 不进入不可变 plan 的摘要循环；由当前操作 admission 绑定准确请求与当前采集 session。持久 metadata/hash 是审计材料，不是权限。

兼容报告的可持久摘要只描述固定规则和稳定的合格结论；当前采集时间、随机 session 与 permit 保存在私有 admission 上下文，不塞进 plan/compatibility hash 后要求每次再核查字节相同。再核查使用同一受保护读取上下文确认事实仍有效；新操作重新采集并签发新事实，不因历史报告同 hash 而复用权限。这样保留确认前后严格一致性，又不将新鲜性或随机值混入不可变计划造成循环或伪漂移。

### 最小接缝

| 接缝                                | 原生接入要求                                                                                                  | 保留的拒绝                                                              |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 身份/探针/绑定                      | D 物理父链、原盘和真实安装使用精确整数；原生 probe 单独版本化，固定系统工具、argv、白名单环境及输出限额       | v1 不升级身份；读取/权限/编码/精度不确定仍拒绝                          |
| compatibility/settings/workload     | 固定安装专属规则与 broker 事实联合签发 native 报告，逐项给出处/缺项                                           | 不接纳任意 JSON、fixture 回调、现场学习的设置字段或普通报告             |
| planning/profile/publication        | 从 native plan 签发准确路径能力；同等级相对句柄及父链保护扩展到唯一真实 profile/control/report 目标           | 不把 fixture 路径正则放宽为整个 D 盘；不接管同名外来根                  |
| approval/console/command            | native-console 来源、真实控制台检查、完整面板、请求绑定、前后再核查与单次消费                                 | verify=true、伪 TTY、重定向输入、自动输入短语均不能签发 native 权限     |
| launch/observe/stop                 | 固定 launcher/argv/env、完整进程/pipe/WSL 归属与已证明收尾；设置窗口沿用 SW 生命周期                          | start/stop 任一规则未齐即不执行；不以名称、PID 或 HTTP 成功替代完整停止 |
| inspection/runner/storage/inventory | 当前 native session＋同组设置租约下运行固定只读 CLI；活动盘/UUID/daemon/swap 完整绑定，按来源安全发布历史诊断 | fixture 不能执行真实 CLI；历史磁盘记录不能恢复 session 或验收能力       |

native provenance 必须由当前固定工厂和 broker 的私有注册表维护。跨进程 helper 的输出只有经父进程核实工具/协议/句柄/当前请求后才成为内部事实；helper 写 native、完整 JSON 或 exit0 本身均不构成可信来源。

原生安全 helper 只能发布准确 profile、授权账本和报告；原 VHD 仅在另批的离线读取器中获得只读访问。写入能力和读盘能力不互换。新原生分支不顺带重构旧 fixture helper、旧视觉或 workflow 算法。

真实 `.wslconfig` 与固定 Windows 工具仅通过准确 C 路径的只读适配读取/执行；不能为兼容原先仅 D 路径的 v2 文件函数而放宽全部 publication 根。原 v1 探针协议不变，新原生协议使用精确身份独立校验。

## 八 七类原生规则及运行边界

| 门槛                      | 关闭所需规则                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------- |
| path_routing              | launcher/frontend/backend/服务/更新及辅助程序的全部应用写入与缓存位置闭合；未知 C 写入不当 OS 例外 |
| backend_environment       | 主/备用启动链、全部子进程与既有 SYSTEM 服务的准确环境和行为；不假定既有服务继承本次 HOME           |
| registration_reuse        | 真实配置下必复用原注册与两盘，排除 import/migration/初始化/新盘分支                                |
| stop_owned                | 本次进程、控制通道、engine/WSL 完整归属及有界停止链；不得停既有 SYSTEM 服务或其他发行版            |
| settings_mutation         | 三文件完整字段、跨文件语义、各阶段和准确临时规则、限额及真实保存行为                               |
| existing_workload_restart | 完整空结论、无自动 provision/外部恢复来源，以及本次可信交接与有效 permit                           |
| automatic_behavior        | 更新、下载、组件、许可、onboarding、hosts/服务和扩展/模块自动行为均符合当前边界                    |

上轮静态定位的 `原文件名.tmp-*` 是 jsonutil 保存 helper 的一条命名证据，不是允许任意 `*.tmp` 的策略，也不证明完整数量、随机规则、失败残留或所有保存分支。fixture 的 `.fixture-01.tmp` 等绝不能注册为 native 模式。完整字段/默认值尚未证明时拒绝，不能第一次启动后学习。

启动计划仍使用准确 D 根、两个 PINATA override、显式单实例锁和封闭环境；清空 WSL/E2E、Electron、Docker/TLS/Buildx 等外部注入。生产默认 endpoint 为空覆盖的既有合同不修改；专用 engine pipe 与 backend 控制 pipe 不能混用，默认连接不一致继续单列阻断。

进程/管道归属需持有准确句柄并绑定 PID、精确创建时间、SID、映像 hash 和父子/本次 session 关系，不能只比较进程名或可复用的 PID。候选 `/app/quit` 须证明作用域和完整 engine/WSL 收尾；发送时核对同一连接的实际 server，不能先查一个 pipe 再无验证地重连另一个实例。已有 SYSTEM 服务不进入本次 stop-owned 集合。

运行观察只允许固定 argv 的 version/info/context 查询及已审查的活动盘/UUID/daemon/swap 探针，不因通用 readonly 分类允许更多 Docker 命令或插件。CLI 原始输出先在受限内存中选取批准字段，不将代理、标签或其他敏感值原样落报告。guest 观察必须使用不会自动启动已停止 VM 的、绑定本次实际运行实例的机制；先查 running 再调用可自动启动发行版的 `wsl -d` 不满足要求，无法证明时返回观察 blocked，不以查询名义暗中重启。

沿用请求最长15分钟、确认等待60秒、面板12 KiB、启动120秒、轮询200ms、停止30秒。离线采集120秒是独立操作上限，发生在原有45秒兼容核查/启动阶段之外；兼容核查只消费并再验证受保护事实，不在其内部偷偷运行120秒采集或刷新阶段时限。未完整观测归属或安全收尾不能保证时，启动前阻断；获准副作用已开始后的失败仅对已归属资源 finally 收尾，设置失败不取消这项资格。未知归属输出 cleanup_uncertain，不强杀、不全局 shutdown、不回滚旧数据。

获准启动仍可能对原 D VHD 产生正常内容、size/mtime 和空间变化，此事实必须纳入单独 START 清单；“不迁移不删除”不是“启动不写盘”。写入路径/增长预算不闭合时不能启动，不用事后超限检测冒充文件系统硬配额。
